## 이전 구현: 출력 선택·위치·법정동 경계·기준자료 업데이트

다음은 출력 유형을 선택하던 이전 단계의 기록이다. `/link`와 MCP Apps의 흐름은 **입력 유형 선택 → 값 입력 → 출력 유형 선택 → 변환**이었다. 입력은 PNU·법정동코드 / 행정동코드 / 주소 / 위치의 네 유형이며, 출력은 같은 네 유형과 법정동 경계 SHP였다. CSV·XLSX 업로드·파일 출력은 이용 화면에서 제외하고 기존 서버 API와 계약 검사는 호환성을 위해 보존했다.

| 범위 | 현재 동작과 한계 |
|---|---|
| PNU·법정동코드 | PNU 19자리 또는 시도 2·시군구 5·읍면동 8·동/리 10자리 출력. 코드만으로 토지 지번을 만들지 않음 |
| 행정동 | 별도 10자리 사전과 검증한 관할 관계로 변환. 여러 관계는 후보로 유지하며 행정동만으로 전체 PNU를 만들지 않음 |
| 주소 | 직접 입력과 실제 카카오 주소 검색. 선택 결과의 확인된 지번만 PNU에 사용하고 예상 지번은 사용하지 않음 |
| 위치 | EPSG:4326·3857·5179·5186·5181 지원. X=경도/동쪽값, Y=위도/북쪽값이며 Proj4js로 입력·출력 좌표계를 변환 |
| 주소·코드↔위치 | VWorld Geocoder 2.0의 정·역지오코딩. 주소 대표 좌표·지역 대표 위치와 구역 중심점·필지 위치를 구분 |
| 법정동 경계 SHP | 시도·시군구·읍면동·리 공식 경계를 조회해 SHP ZIP 생성. 개별 필지·행정동 경계가 아니며 출력은 EPSG:4326만 지원 |
| 기준자료 | `/link/reference`에서 출처·버전·원천 기준일·마지막 확인·반영 시각을 분리 표시하고 법정동·행정동 사전을 함께 확인 |

일반 직접 변환은 최대 200행, 위치 조회는 최대 20행이다. 위치→위치는 외부 주소 원천 없이 좌표계만 변환한다. 주소·관할 조회는 VWorld 실제 응답을 사용하며 원천의 코드와 현재 사전 버전이 맞지 않으면 오류로 구분한다. 지역코드→위치는 지역명으로 얻은 대표 위치다. 도형의 centroid를 계산하거나 개별 토지의 위치로 승격하지 않는다. 모든 결과의 실제 필지 확인은 `not_checked`다.

경계 출력은 `server/services/link/boundary.ts`를 HTTP `POST /api/link/boundary`와 앱 전용 `geo_link_boundary`가 함께 사용한다. 2·5·8·10자리 법정구역 코드 최대 20개를 받아 VWorld 2D Data API의 해당 레이어를 조회한다. Polygon·구멍·MultiPolygon을 SHP/SHX/DBF/PRJ/CPG와 `metadata.json`으로 묶는다. DBF는 ASCII 코드·원천 ID를 담고 한글 명칭과 출처·코드 사전 버전·확인 시각은 JSON에 보존한다. API 키·등록 서비스 URL이 필요하고 폐지·미등록 코드, 잘못된 도형, 과도한 응답·도형·점 수는 거절한다.

### 한국 날짜 기준 공유 업데이트

`server/services/link/reference-updates.ts`가 `GET /api/link/references`, `POST /api/link/references/update`와 기준자료 화면의 공통 상태를 관리한다. 한국 시간(`Asia/Seoul`)의 당일 기록을 영속 경로 `.data/reference/link/updates/`에 저장하고, `LINK_REFERENCE_UPDATE_DIR`로 변경할 수 있다. 모든 사용자가 같은 기록을 읽고 동시 요청은 같은 실행을 공유한다. 시도 번호 파일의 독점 생성으로 같은 공유 경로를 쓰는 서버 프로세스의 중복 실행도 막는다.

당일 확인한 자료는 다시 다운로드·반영하지 않는다. 새 확인에서 원문이 같으면 `checkedAt`만 갱신하고 기존 활성 버전·반영 시각을 보존한다. 실패·중단 때는 이전 정상본을 유지하며 5분 재시도 대기 후 실패한 원천만 다시 확인한다. 출처의 기준일(`sourceDate`), 확인 시각(`checkedAt`), 반영 시각(`activatedAt`/`ingestedAt`)은 서로 다른 값이다. 갱신 대상은 로컬 법정동·행정동/관할 사전이며 카카오 주소 검색이나 VWorld의 실시간 위치·경계 서비스를 로컬로 갱신하는 버튼은 아니다. 운영 자동 스케줄은 설치하지 않았다.

## 이전 단순화·주소 검색 구현 이력 (위치·경계 추가 전)

사용자 피드백에 따라 `/link`와 연계 MCP Apps의 이용 흐름을 **입력 유형 선택 → 값 입력 → 출력 유형 선택 → 변환 결과**로 줄였다. 이 단계의 입력·출력 그룹은 PNU·법정동코드 / 행정동코드 / 주소였다. 사용자가 먼저 명시적으로 입력 체계를 고르며 자동 판별을 기본으로 삼지 않는다. 선택 열·주소 표시·행 처리 옵션·작업 필터는 화면에서 제외했다.

| 입력 | 선택 가능한 결과 |
|---|---|
| PNU·법정동코드 | 주소·PNU/법정동코드 또는 확인된 행정동 관계 |
| 행정동코드 | 행정동 사전의 명칭·검증된 법정동 관계 |
| 주소 | PNU/법정동코드 또는 확인된 행정동 관계 |

PNU·법정동코드 출력일 때에만 전체 PNU(19자리)·시도(2자리)·시군구(5자리)·읍면동(8자리)·동/리(10자리)의 출력 단위를 선택한다. 법정동과 행정동을 같은 코드로 취급하지 않으며 사전 미준비·관계 미확보와 정상 미일치를 구분한다. 코드만으로 필지의 지번을 만들지 않는다. 최대 200행을 공통 동기 변환 서비스로 즉시 처리하고, 결과는 입력과 출력 두 열 및 복사로 제공한다. 오류 설명과 후보 선택은 필요한 행에만 표시한다. 입력을 바꾸면 이전 결과를 비운다.

웹의 주소 입력에는 주소 검색을 추가한다. 외부 검색에서 사용자가 고른 주소에 확인된 지번주소가 있는 경우에만 PNU 변환에 사용한다. 원문 도로명주소와 지번주소를 구분하며 추정 `autoJibunAddress`를 실제 확인 지번으로 쓰지 않는다. 검색 SDK의 실패와 지번 미확인 상태를 별도로 안내한다.

- 실제 자료는 Git 제외 영속 경로 `.data/reference/link/versions/`에 원문·snapshot·manifest·체크섬과 함께 저장한다. 새 환경에서는 재수집해야 한다.
- 소형 fixture와 합성 전국 규모 복구 테스트 자료는 별도 테스트 경로에 있으며 운영 사전으로 노출하지 않는다.

원문에는 상위 코드 열이 없어 공식 전체 명칭의 등록 부모 경로를 사용한다. 시 아래 일반구는 실제 시 부모 관계로 연결하고 하위 조회는 관계를 따라 수행한다. 특정 시 이름·코드를 하드코딩하지 않는다. 이는 별도 공식 관할 관계 파일이나 전 시점 이력을 검증한 결과는 아니다. 상세 출처·조건·재현은 [기준자료 문서](data-sources.md)에 있다.

검증 후 append-only 활성화 이력을 먼저 기록하고 활성 포인터를 갱신한다. 이동·리네임 금지 합의 때문에 rename 방식의 포인터 교체는 사용하지 않았다. 포인터 기록 중단 시 이전 정상 활성화 이력에서 복구한다. 미공개 버전의 중단 파일은 검증 후 복구하고, 공개 이력이 있는 손상 버전은 덮어쓰지 않는다.

현재 코드와 제안 명세의 차이는 `/api/link/jobs/:id`가 상태와 페이지 결과를 함께 제공하고 별도 `/rows` 경로를 만들지 않은 점이다. 재실행은 `/rerun`, 웹 권한 전달은 `/claim`을 사용한다. 파일 생성은 POST `/export`, 읽기는 GET `/artifacts/:artifactId`로 분리했다. CSV 선택 열에도 입력/후보 ID·기준 버전·옵션·오류 요약은 필수 보존한다.

## 권한·보관·한도

웹은 HttpOnly·SameSite 소유자 쿠키, 앱은 별도 랜덤 접근 토큰, MCP SDK는 `Mcp-Session-Id`로 같은 작업 소유권을 유지한다. 디스크에는 권한 토큰의 해시만 저장한다. 작업 UUID만 아는 다른 소유자는 조회·출력·파일 접근이 차단된다. MCP 세션은 만료·종료를 검사하고 파일 GET도 같은 세션 헤더를 검증한다. SDK 이용자는 파일 요청에 `transport.sessionId`를 전달한다.

모델의 `content`·`structuredContent`에는 접근 토큰과 파일 본문을 넣지 않는다. 앱 권한·호스트 다운로드 파일은 `_meta`로 전달하며 실제 호스트의 전달 정책 확인은 별개다. 토큰을 포함한 웹 링크는 fragment에서 메모리로 읽고 즉시 주소에서 제거한 뒤 권한을 claim한다. 모든 새 API는 `private, no-store` 응답과 `no-referrer` 정책을 사용한다.

초기 설정값은 다음과 같으며 환경변수로 조정한다.

| 항목 | 기본값 |
|---|---:|
| 동기 입력 | 200행 |
| 업로드·정규화 입력 | 20MiB |
| 입력 행·열 | 50,000행·200열 |
| XLSX 실제 압축 해제 합계 | 40MiB |
| 원본 행·셀 | 64KiB·10,000자 |
| 동시 작업·대기 | 2개·20개 |
| 작업 실행 시간 | 120초 |
| 결과 | 100,000행·60MiB |
| 웹·모델 미리보기 | 50행·10행 |
| 모델 파일 미리보기 | 10행·10열·셀 300자 |
| 접근 보관 기간 | 24시간 |

ZIP 중앙·로컬 항목, 실제 inflate 상한·CRC·항목 수·경로·암호화·매크로·외부 링크를 확인하며 파일 경로로 압축을 풀지 않는다. 새 외부 URL 수집이나 공개 로컬 경로 입력은 제공하지 않는다. 작업은 200행씩 처리하며 중단 후 부분 재개를 지원하지 않는다. 재시작된 프로세스의 실행 중 작업은 조회 시 실패로 표시하고 원본으로 재실행한다.

삭제 금지 합의에 따라 **물리 삭제·이동·리네임을 수행하지 않았다**. 24시간 후 API 접근은 차단하지만 디스크 자료는 남는다. `link:maintenance`는 만료 현황만 출력한다. 운영 갱신·물리 정리 스케줄을 설치하지 않았으며 등록 방법은 기준자료 문서에 설명했다. 기준자료 업데이트는 같은 영속 경로의 당일 실행을 공유하며 기존 파일 작업 큐는 단일 서버 인스턴스 기준이다.

## 초기 구현 검증 결과와 재현 (69개 검사 시점)

실행 환경은 Windows, AMD Ryzen 7 7700, Node `v22.19.0`, 설치된 Chrome headless다. 현재 Node는 저장소·Nuxt의 지원 버전보다 낮다는 경고가 발생한다. 빌드·실행은 확인했지만 운영에는 설치 패키지가 요구하는 Node 버전을 사용해야 한다.

새 연계 앱은 실제 Claude·ChatGPT 호스트에서 실행하지 않았다. MCP 프로토콜·공식 SDK 클라이언트·모의 호스트 검증과 실제 AI 호스트 실측을 구분한다. 기존 시각화 카탈로그/실제 산출물 검사와 웹 경로·도구 목록은 확인했지만 Docker 변환 71개·Unreal 렌더링·전국 개별 필지 자료를 다시 실행·수집하지 않았다.

## 운영 공개 전 남은 사항

**로컬 기술 흐름은 구현·검증했으며 공개 배포 준비는 미완료다.** 다음 사항을 운영 환경에서 확인해야 한다.

- 지원 Node 버전, HTTPS·프록시의 신뢰 설정, 영속 볼륨·디스크 용량·접근권한·백업, 호스트별 MCP 세션/다운로드 전달.
- 자동 확인이 필요하면 갱신 스케줄 설치와 실패 알림, 승인된 보관·물리 정리 정책을 준비한다. 수동 기준자료 업데이트와 만료 접근 차단은 구현되어 있다.
- 현재 설치 트리 `npm audit --omit=dev`는 21건(낮음 4·보통 7·높음 10)을 보고했다. 기존/신규 간접 의존성의 정밀 분류·일괄 업그레이드는 하지 않았고 강제 자동 수정도 하지 않았다.
- 기존 시각화 URL 수집의 DNS rebinding 한계와 인증 없는 기존 `/api/jobs` 등은 그대로다. 새 `/link`의 권한 검사를 전체 서버의 공개 보안 완료로 일반화하지 않는다.
- 새 앱의 실제 AI 호스트 검증, 사내 자료가 호스트에 전달되는 범위와 보관 정책 확인.
- VWorld 2D 데이터 API 권한·등록 도메인을 확인해 실제 경계 조회·다운로드를 검증해야 한다. 행정동 원문 공개 재배포 조건도 제공기관에 확인한다. 우편번호·개별 객체 전체 목록·공공 속성은 추가 검증 범위이며 가짜 관계·좌표·경계를 제공하지 않는다.
