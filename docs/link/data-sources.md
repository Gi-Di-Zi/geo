# 주소·코드 연계 기준자료

확인일: 2026-10-30. 운영 법정구역 사전과 테스트 fixture는 별개다. 코드 사전으로 만든 주소·PNU 형식값은 실제 필지 존재를 확인한 결과가 아니다.

`/link/reference`에서 로컬 법정동·행정동 사전의 출처·버전·원천 기준일·마지막 확인·반영 시각을 확인하고 업데이트한다. 카카오 주소 검색과 VWorld 위치·경계는 외부 서비스에 실제 조회하며 이 로컬 업데이트 대상에 포함하지 않는다.

| 자료 | 현재 사용 방식 | 실제 확인 상태 |
|---|---|---|
| 법정동 코드 | code.go.kr 전국 전체자료를 로컬 사전으로 검증·활성화 | 53,403건(현존 20,560·폐지 32,843) 확보 |
| 행정동·관할 관계 | 행정안전부 2026-10-12 시행본을 별도 로컬 사전으로 활성화 | 코드 3,925건, 관계 21,837건 중 21,830건 검증 |
| 주소 검색 | 카카오 우편번호 서비스에서 사용자가 실제 주소를 선택 | 실제 Chrome 검색·선택·PNU 변환 확인 |
| 주소↔위치 | VWorld Geocoder 2.0 정·역지오코딩 | 실제 주소·좌표·관할 코드 응답 확인 |

[공공데이터포털 연결 카탈로그](https://www.data.go.kr/catalog/15077871/openapi.json)는 제공기관, 무료 제공, ‘이용허락범위 제한 없음’과 API 경로를 안내한다. 다운로드 원문·가공 결과에는 제공처와 버전을 유지한다. 카탈로그의 실시간 갱신 표시는 API 설명이며 전체 ZIP가 매일 새로 발행된다는 뜻이 아니다. 공개 재배포 전에는 해당 시점의 제공처 이용조건을 다시 확인한다.

[법정동코드 API](https://www.data.go.kr/data/15077871/openapi.do)는 별도 활용신청·서비스키 경로다. 법정동 사전 구현은 무키 전체자료 다운로드를 사용하며 이 API를 호출했다고 표시하지 않는다. 행정동·관할 관계는 별도로 실제 확보한 행정안전부 최신 시행본을 사용하며 이전 게시물에 고정하지 않는다.

## 행정동 사전과 실시간 조회 원천

행정동 사전은 [행정안전부 2026-10-12 시행 게시물](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=130109)의 `jscode20261012.zip`을 사용한다. 버전은 `mois-admin-20261012-a82bb15f6a8c3563`, 게시일은 `2026-10-08`, 원천 기준일은 `2026-10-12`다. 10자리 코드 3,925건은 시도·시군구·읍면동을 포함한다. 관계 21,837건 중 21,830건은 같은 배포본 법정동 등록을 검증했으며 출장소 자기참조 7건은 보존하되 변환에서 제외한다. 코드 체계·원문 열·검증·이용조건은 [행정동 자료 문서](administrative-source.md)에 있다. 개별 공공누리 적용을 확인하지 못해 공개 재배포 전 제공기관의 이용조건 확인이 필요하다.

[카카오 우편번호 서비스](https://postcode.map.kakao.com/guide)는 검색 버튼 클릭 시 공식 SDK를 불러온다. 사용자가 선택한 확정 지번만 PNU에 사용하며 예상 지번을 확정값으로 취급하지 않는다. 실제 ‘서울 종로구 사직로 161’ 검색→‘서울 종로구 세종로 1-57’ 선택→PNU `1111011900100010057` 변환을 Chrome에서 확인했다. 검색 결과와 필지 대장의 존재 확인은 구분한다.

[VWorld Geocoder 2.0](https://www.vworld.kr/dev/v4dv_geocoderguide2_s001.do)은 주소→위치와 위치→주소·법정동/행정동 코드를 실제 조회한다. 서버 `VWORLD_KEY` 또는 기존 `NUXT_PUBLIC_VWORLD_KEY`를 사용하며 문서·로그에 키를 기록하지 않는다. 실제 정지오코딩 ‘서울 종로구 사직로 161’과 역지오코딩 `126.9769, 37.5759`의 응답을 `.data/link-location-smoke.json`에 남겼다. 지역코드→위치는 지역명을 조회한 대표 위치이며 도형 중심점(centroid)·필지 좌표·관할 경계 확정값이 아니다. 원천은 기준일을 제공하지 않아 `sourceDate: null`과 실제 `checkedAt`을 구분한다.

좌표계 변환은 Proj4js `2.22.0`으로 EPSG:4326·3857·5179·5186·5181을 지원한다. 입력·출력은 X=경도/동쪽값, Y=위도/북쪽값이다. 위치→위치의 순수 좌표계 변환은 주소·관할 서비스를 호출하지 않는다.

[VWorld 2D Data API 법정구역 경계](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=ademd)는 시도 `LT_C_ADSIDO_INFO`, 시군구 `LT_C_ADSIGG_INFO`, 읍면동 `LT_C_ADEMD_INFO`, 리 `LT_C_ADRI_INFO`를 법정구역 코드로 조회한다. `VWORLD_KEY`와 키에 등록한 서비스 URL `VWORLD_DOMAIN`이 필요하다. **현재 실제 요청은 `INCORRECT_KEY`로 거절되었다. 2D 데이터 API 권한·등록 도메인 확인 전에는 실경계 다운로드 성공으로 보고하지 않는다.** SHP 출력은 EPSG:4326만 지원하고, `sourceDate: null`·조회 시각·출처·사전 버전을 메타데이터에 남긴다. 합성 Polygon·구멍·MultiPolygon 원천 응답으로 만든 ZIP의 SHP/SHX/DBF 독립 해독 등 18개 검증은 통과했다. 이는 실제 원천 접근 검증과 별개다.

우편번호·필지/건물 전체 목록·공공 속성은 추가 원천 검증 범위다. [주소기반산업지원서비스 자료 안내](https://business.juso.go.kr/jst/jstAddressDownload?menu=7)는 후속 연결 대상으로 남긴다. 건물관리번호를 필수 허브로 사용하지 않는다.

## 정규화와 계층의 한계

코드는 10자리 문자열로 유지한다. 원문의 현존·폐지 상태를 보존하고 과거 코드를 현재 코드로 자동 치환하지 않는다. 시도 개수·특정 도시 코드·명칭을 고정하지 않는다.

전체자료에는 상위 코드 열이 없으므로 공식 원문의 전체 명칭 경로에서 마지막 명칭을 제외한 등록 구역을 부모로 연결한다. 예를 들어 ‘경기도 수원시 권선구’의 부모는 실제 등록된 ‘경기도 수원시’다. 따라서 시 전체 하위 구역은 부모 관계를 따라 조회하며, 동일한 5자리 접두어만으로 대체하지 않는다.

같은 전체명이 과거·현재 코드에 함께 있으면 같은 상태를 우선하고 코드의 공통 부분으로 연결한다. 이 방식은 원문 명칭 경로에 근거한 정규화이며 별도의 공식 관계 파일과 전 시점 이력을 대조한 결과는 아니다. 부모 등록·순환을 검사하지만 개별 유효일, 선후행 관계, 과거 특정 시점의 정확한 관할을 보장하지 않는다. 해당 기능 확장 때에는 공식 관계 자료를 별도로 검증해야 한다.

## 저장·활성화·재현

기본 영속 경로는 `.data/reference/link/`이며 `LINK_REFERENCE_DIR`로 변경한다. 사용자 입력·작업의 `.data/link/`와 분리한다. `.data`는 Git에서 제외되므로 새 환경에서는 다음 명령으로 자료를 다시 수집한다.

```powershell
npm.cmd run link:reference -- --check
npm.cmd run link:reference -- --status
npm.cmd run link:administrative -- --check
# 같은 날 다시 확인해야 할 때
npm.cmd run link:reference -- --force
# 운영자가 확보한 공식 ZIP 또는 UTF-8 TXT를 검증해 반영할 때
npm.cmd run link:reference -- --import C:\reference\legal-codes.zip
```

`versions/<version>/`에는 원문·정규화 snapshot·manifest를 저장한다. manifest는 출처, 인증·이용조건 설명, 원문·정규화 체크섬, 행 수, 상태, 파일일, 확인·반영 시각, 검증 항목을 남긴다. 필수 열·10자리 문자열·중복·부모 등록·순환·전국 범위·이전 정상본 대비 현존 코드 급감을 검사한다. 불완전 자료나 현존 코드가 10% 이상 감소한 자료는 자동 반영을 중단한다. 이 검사는 보수적 수집 이상 탐지이며 전국 행정변경의 의미를 심사하는 절차는 아니다.

검증한 버전만 활성화한다. 이미 manifest로 확정한 버전은 덮어쓰지 않는다. manifest 기록 전에 중단된 미공개 파일은 같은 원문을 다시 검증하여 재작성할 수 있다. 실패하면 이전 정상본을 유지한다. 작업은 시작 시점 snapshot을 고정하므로 갱신 전후 행이 한 작업에 섞이지 않는다.

파일 이동·리네임 금지 합의 때문에 `active.json` 교체에 rename을 사용하지 않는다. 먼저 append-only `activations/` 이력을 기록하고 포인터를 갱신한다. 포인터 기록이 중단되면 마지막으로 검증되는 활성화 이력에서 복구한다. 같은 원문을 재확인하면 확인 시각만 갱신하고 기존 버전과 최초 반영 시각을 보존한다.

## 갱신과 보관 운영 상태

`/link/reference`의 업데이트 버튼은 한국 날짜(`Asia/Seoul`, KST) 기준 당일 상태를 서버에 저장한다. 법정동·행정동/관할 자료의 확인 기록은 모든 사용자가 공유한다. 같은 당일 확인이 끝났으면 다시 적용하지 않으며, 진행 중 동시 요청은 같은 실행을 공유한다. `.data/reference/link/updates/<한국 날짜>/<시도 번호>.json`을 독점 생성해 같은 경로를 쓰는 서버 프로세스 사이에서도 중복 실행을 막는다. 경로는 `LINK_REFERENCE_UPDATE_DIR`로 변경할 수 있다. 실패·중단 시 이전 정상본을 계속 사용하며 5분 대기 후 실패한 원천만 재시도한다.

`sourceDate`는 제공처의 자료 기준일, `checkedAt`은 마지막 확인 시각, `activatedAt`/`ingestedAt`은 로컬 반영 시각이다. 당일 재확인이나 같은 원문 수신 때문에 기준일·반영 시각을 오늘로 바꾸지 않는다. 법정동 전체자료는 기준일 미제공이고 행정동 확보본의 기준일은 `2026-10-12`다.

운영 자동 스케줄은 **설치하지 않았다**. 자동 확인이 필요하면 프로젝트 디렉터리를 작업 경로로 지정하고, 지원되는 Node·의존성을 설치한 계정에서 하루 한 번 `npm.cmd run link:reference -- --check`와 `npm.cmd run link:administrative -- --check`를 실행하도록 등록할 수 있다. 각 명령도 한국 날짜당 한 번 확인하고 `checks/`에 `updated / no_change / failed` 등을 기록한다. 운영자가 같은 날 명시적으로 재확인하려면 CLI의 `--force`를 사용한다. 화면의 실패 재시도는 5분 대기 후 제공한다. 원천 자체가 매일 새로 발행된다고 표현하지 않는다.

사용자 파일·결과는 기본 24시간 후 API 접근을 차단한다. `LINK_JOB_TTL_MS`로 조정할 수 있다. `npm.cmd run link:maintenance`는 만료 건수 inventory를 출력한다. 전역 삭제 금지 합의에 따라 물리 삭제는 구현·실행하지 않았고 정기 삭제 스케줄도 설치하지 않았다. 접근 만료와 디스크 삭제는 다르며, 운영 전 저장공간·보관 정책을 정해야 한다. 기준 사전은 사용자 임시파일의 보관 대상에 포함하지 않는다.

## 테스트 자료

`tests/link/fixtures/reference.ts`는 명시적인 소형 fixture다. `reference.test.ts`가 생성하는 합성 전국 규모 자료는 `.data/link-tests/reference/<임의 ID>/`에 격리하며 운영 경로로 활성화하지 않는다. 삭제 금지 합의에 따라 테스트 산출물도 자동 삭제하지 않는다. 실제 다운로드 ZIP의 CRC·인코딩 확인과 합성 fixture의 변환·오류·복구 검증을 구분한다.
