# 위치 입력·출력과 주소 조회

위치는 식별자 코드와 구분해 숫자 좌표로 검증한다. 기본 위경도는 `EPSG:4326`, 지원 투영좌표는 `EPSG:3857`, `EPSG:5179`, `EPSG:5186`, `EPSG:5181`이다. 좌표계 변환은 Proj4js를 사용하며 주소·법정동·행정동 조회는 별도 VWorld 원천을 호출한다.

이용 화면에서는 변환 전 결과 좌표계를 묻지 않는다. 변환 후 성공한 위치 결과 안의 좌표계 선택으로 해당 좌표만 바꾼다. 원본 X·Y·EPSG를 보존해 매번 원본에서 재투영하며 주소·관할 조회와 경계 다운로드를 다시 실행하지 않는다. 웹은 공통 좌표 함수를 브라우저에서 실행하고 MCP Apps는 기존 `geo_link_resolve`의 `inputType=location`, `target=location` 순수 변환만 호출한다. 복사에는 현재 표시한 좌표와 EPSG를 반영한다. 위치 입력의 입력 좌표계 선택은 유지한다.

## 좌표 순서와 범위

이 도구의 **X는 경도 또는 동쪽값(easting), Y는 위도 또는 북쪽값(northing)**이다. 일부 국내 EPSG 정의의 공식 축 이름·순서는 북쪽값을 먼저 쓰므로 원문 파일의 축 순서와 이 도구의 입력 순서를 확인해야 한다. 두 값을 자동으로 바꾸거나 EPSG를 추측하지 않는다.

| EPSG | 표시 | 단위·특징 |
|---|---|---|
| 4326 | WGS84 경도·위도 | 도, X 경도·Y 위도 |
| 3857 | Web Mercator | 미터 |
| 5179 | KGD2002 / Unified CS, UTM-K | GRS80·중앙경도 127.5°·축척 0.9996·가산값 동 1,000,000m/북 2,000,000m |
| 5186 | KGD2002 / 중부원점 2010 | GRS80·중앙경도 127°·가산값 동 200,000m/북 600,000m |
| 5181 | KGD2002 / 중부원점 | GRS80·중앙경도 127°·가산값 동 200,000m/북 500,000m |

정의·좌표 순서의 근거는 [Proj4js 문서](https://github.com/proj4js/proj4js), [SGIS 공식 UTM-K 안내](https://sgis.mods.go.kr/view/newhelp/us_help_30_0), [Esri 공식 투영좌표계 정의 목록](https://developers.arcgis.com/rest/services-reference/enterprise/43b51ca910d5d49ba01f1d5cc720fd5a/pcs_pdf_11.5.pdf)이다. KGD2002↔WGS84는 이 도구에서 동등 근사로 처리하며 측량급 정확도를 보장하지 않는다.

## 실제 주소·코드 연결 원천

[VWorld Geocoder 2.0 공식 안내](https://www.vworld.kr/dev/v4dv_geocoderguide2_s001.do)의 `https://api.vworld.kr/req/address`만 호출한다. 임의 URL·사용자 지정 서버를 받지 않는다. 기존 서버 설정의 `VWORLD_KEY`, 없으면 기존 `NUXT_PUBLIC_VWORLD_KEY`를 사용한다. 새 유료 서비스나 계정을 만들지 않았고 키의 값·요청 URL·원천의 오류 원문을 로그·결과에 기록하지 않는다.

- `getCoord`: 주소 또는 구역 명칭에서 WGS84 좌표를 받는다. 도로명주소는 `road`, 지번·지역명은 `parcel` 유형으로 조회한다. `refine=false`로 임의의 주소 보정을 요청하지 않는다.
- `getAddress`: 입력 좌표를 WGS84로 변환한 뒤 `type=both`로 조회한다. 실제 지번 응답을 주소와 법정동코드의 우선 원천으로 사용하며, 행정동은 별도의 `level4AC` 필드에서 읽는다.
- 지번 응답의 `structure.level4LC`는 법정동코드다. **도로명 응답의 같은 필드는 도로명코드이므로 법정동코드로 쓰지 않는다.** 10자리 문자열만 코드로 채택한다.
- 지번 응답이 없고 도로명만 있으면 `parcelAddress`는 빈 문자열로 유지한다. 그 도로명 건물번호를 토지 지번으로 바꾸지 않는다. PNU를 구성하려는 호출부는 반드시 확정된 `parcelAddress`만 사용해야 한다.
- 원천은 응답에 자료 기준일을 제공하지 않으므로 `sourceDate: null`이다. `checkedAt`은 실제 API 응답을 받은 시각이며 캐시 재사용 시에도 최초 응답 시각을 유지한다.

## 결과의 의미

| method | 의미 |
|---|---|
| `input_point` | 사용자가 입력한 좌표 또는 그 좌표계 변환 |
| `address_point` | 원천이 반환한 주소 대표 좌표. 필지 중심점이나 건물 전체 경계가 아님 |
| `region_representative` | 지역 명칭으로 조회한 원천의 대표 위치. 구역의 기하학적 중심·행정청 위치·포함 관계를 확정하지 않음 |
| `reverse_geocoded` | 원천이 입력 위치에 대해 돌려준 주소와 코드. 공유 경계의 엄밀한 포함 관계나 지적 대장 존재 확인이 아님 |

행정동·법정동 구역 코드에서 점 하나를 얻는 것은 원천의 대표 위치 조회다. 그 점을 다시 역지오코딩했을 때 원래 구역과 정확히 일대일로 대응한다고 보장하지 않는다. 개별 필지의 존재와 관할 경계는 별도 자료로 확인해야 한다.

## 우편번호

우편번호(기초구역번호)는 VWorld 역지오코딩 응답의 `zipcode`로 정한다. 지번이 있으면 대표점 역조회 결과가 같은 법정동코드·지번일 때만, 도로명주소는 원천이 붙인 괄호(동·건물명)를 뺀 도로명주소가 같을 때만 쓰고, 좌표 입력은 그 위치의 결과를 쓴다. 법정동·행정동·시군구처럼 구역만 있으면 우편번호가 여러 개라 정하지 않는다. 원천이 지번 뒤에 붙이는 지목 약자(`171-1학`)는 비교 전에 뗀다. 시군구로 없는 5자리 숫자는 우편번호 입력으로 보고, 우편번호로 주소 목록을 찾는 자료는 없으므로 웹에서는 그 번호로 카카오 주소 검색을 열고 MCP에서는 웹 주소 검색으로 안내한다. 우편구역 경계는 제공하지 않는다. 이 때문에 PNU 행은 주소→위치 조회 뒤 위치→주소 조회를 한 번 더 한다(같은 요청 안에서는 캐시).

## 호출 제한과 실패

위치 기능은 한 번에 20행을 초기 상한으로 안내하며 공통 실행부가 이를 적용한다. 원천 호출은 전역 2개 동시 실행, 대기 40개, 요청당 10초, 응답 1MiB로 제한한다. 동일 요청은 실행 중 Promise를 공유하고 성공 응답을 최대 60초·256개까지 메모리에 보관한다. 사용자 주소·좌표를 캐시 파일이나 로그로 저장하지 않는다. 리다이렉트는 따라가지 않는다.

지원되지 않는 EPSG·잘못된 X/Y·범위 오류는 `invalid`, 정상 원천의 미일치는 `not_found`, 키 미설정·인증/도메인·호출 한도·통신/응답 장애는 `unavailable`로 구분할 수 있는 `LocationError`를 반환한다. API 장애를 ‘그 주소가 존재하지 않음’으로 표시하지 않는다. `getLocationCapabilities().state`는 키 설정 여부이며 원천 가동 상태를 미리 조회한 건강 점검 결과는 아니다.

## 검증

`tests/link/location.test.ts`는 순수 좌표 파싱·5개 CRS 왕복·공식 원점·축/범위·도로명코드 오인 방지·원천 미일치/장애/비밀 미노출·중복 요청·동시 제한을 검사한다. 모의 API 테스트는 실제 네트워크 검증과 구분한다.

2026-10-30 기존 VWorld 키로 공개 주소와 위치만 소량 실제 조회했다. 사직로 161의 주소 좌표, 세종로 지번의 역지오코딩 법정동 `1111011900`과 행정동 `1111051500`, 종로구·청운동·청운효자동의 지역 명칭 대표 좌표를 확인했다. 키와 전체 요청 URL은 결과에 남기지 않았다. 운영 배포·실제 AI 호스트·측량 정확도는 검증하지 않았다.
